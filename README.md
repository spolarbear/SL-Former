# SL-Former: Surrogate Model for Seismic Response of Frame Structures via Micro-element Voxel Tokenization

![Python](https://img.shields.io/badge/Python-3.12-blue)
![PyTorch](https://img.shields.io/badge/PyTorch-2.x-orange)
![PostgreSQL](https://img.shields.io/badge/PostgreSQL-16-336791)
![License](https://img.shields.io/badge/License-MIT-green)

**A deep surrogate model that directly tokenizes structural frame members into 128-bit voxel micro-elements and predicts full seismic displacement time-histories — bypassing expensive nonlinear OpenSees simulations.**

---

## 🌟 Highlights

- **128-bit micro-element voxel encoding** — each grid cell stores 6-face through-connectivity, per-face cross-section (4-bit width + 4-bit height), per-face material, and 3-axis nodal offsets, capturing member topology *and* stiffness in a single discrete token.
- **Three physics-aware embedding strategies** (`rich8` / `hexa9` / `basic5`) — stiffness-similar micro-elements are mapped to *nearby* embedding vectors via PCA of physical vectors, verified by class-separation/cluster metrics.
- **Large-scale dataset** — 63,861 OpenSees nonlinear samples from 63,400 RC frame structures × 236 real ground motions, 5 plan shapes (rectangular / T / L / C / U), per-floor loads, and variable member sections.
- **Strong accuracy** — displacement prediction reaches **R² = 0.935** (overall) and **peak R² = 0.970** on 4,000 held-out validation samples, with **relative MAE ≈ 3.8%**.
- **Reproducible & modular** — PostgreSQL-backed data pipeline, Optuna hyper-parameter search, 16-variant ablation suite, and publication-grade (300 dpi PDF/PNG) visualization tools.

## 🧠 Method Overview

### 1. Micro-element voxel encoding (128 bit / cell)

The frame model is cut with a **1 m voxel grid** (64×64×64 over a 64 m space, origin-aligned). Each non-empty cell encodes a 128-bit integer:

| Field | Bits | Meaning |
|---|---|---|
| 6-face through-connectivity | bit 0–5 | `-X +X -Y +Y -Z +Z` — infers member type (column `-Z+Z`, X-beam `-X+X`, Y-beam `-Y+Y`) |
| Per-face section (width×height) | bit 6–53 | 6 faces × 8 bits (4-bit width + 4-bit height level, 0.2 m module) |
| Per-face material | bit 54–77 | 6 faces × 4 bits |
| Nodal offsets (X / Y / Z) | bit 78–89 | 3 × 4-bit signed offsets (−8…+7), sub-cell position |
| Reserved | bit 90–127 | future extension |

The 128-bit code is decoded back to member geometry, cross-sections, and stiffness (`decode_cell`), enabling lossless round-trip.

### 2. Three physics-aware embedding strategies

Each discrete micro-element token is mapped to a **physical vector** that is PCA-projected to the embedding dimension, so *stiffness-similar elements start nearby* in embedding space (then fine-tuned during training):

| Mode | Dimension | Physical content |
|---|---|---|
| `rich8` | 8 | type gradient, column EI, beam EI, column area, beam area, offset X/Y, fill strength |
| `hexa9` | 9 | **3 pair-face shear stiffness GA + bending stiffness EI** (X/Y/Z directions), type, fill, offset magnitude |
| `basic5` | 5 | type gradient, column EI, beam EI, offset X/Y |

**PCA interpretability** (44-token vocabulary, augmented to 216 with offset variants):

| Metric | `rich8` | `hexa9` | `basic5` |
|---|---|---|---|
| Class separation ↑ | 1.151 | **1.560** | 1.367 |
| Cluster radius ↓ | 0.269 | **0.167** | 0.572 |

`hexa9` (six-face stiffness) separates member types most cleanly because it explicitly encodes the *spatial direction* of stiffness (columns → Z, beams → X/Y).

### 3. Transformer backbone (SLFormer)

- Token micro-element features → learnable `nn.Embedding` (optionally physics-initialized)
- V2 modern transformer: Pre-LN, **Rotary position encoding (RoPE)**, QK-norm attention, **FiLM** structural conditioning, local convolution, SwiGLU FFN, drop-path
- **Bypass** branch: ground-motion → displacement residual shortcut
- 21-dim structural parameter vector `p` (geometry + shape ID + per-floor loads) injected as explicit conditioning

## 📊 Dataset

Built and managed in **PostgreSQL** (`slf_sim`, `_v3` suffix tables):

| Item | Value |
|---|---|
| Ground motions (real records) | 236 (from PEER NGA `dzb/`) |
| Structures | 63,400 |
| Samples (structure × motion × PGA) | 63,861 (49,481 completed) |
| Plan shapes | rect / T / L / C / U |
| Stories | 2–11 |
| Spans | 2–4 per direction, 3–8 m |
| Story heights | 3–6 m |
| Floor loads | 10 / 15 / 20 / 25 kPa per floor |
| Member sections | 200 mm module, bottom-to-top taper |

**Sampling strategy** (for training): stratified uniform sampling over *number of stories × response magnitude × structure form* — keeps the validation set diverse and unbiased.

## 🚀 Quick Start

### 0. Environment

```bash
# Python 3.12 + PyTorch (CUDA) + PostgreSQL + OpenSeesPy
conda env create -f environment.yml   # or use your own env
pip install numpy torch matplotlib scipy psycopg2-binary pandas \
            openseespy optuna tqdm
```

> **Note**: OpenSeesPy is required only for simulation/sample generation (`db_generate_samples.py`). Training, evaluation, and visualization do **not** need OpenSees.

### 1. Initialize database & generate samples

```bash
python db_setup.py                                          # create schema (idempotent)
python db_generate_samples.py --num 5000 --n_waves 50 --workers 12   # nonlinear OpenSees sims
```

### 2. (Optional) Hyper-parameter search with Optuna

```bash
python optuna_search.py --trials 50 --epochs 40 --objective score --use_db --max_samples 20000
```

### 3. Train

```bash
# token encoding (default, physics-initialized embedding)
python train_voxel.py --use_db --max_samples 80000 --epochs 300 --out ./models_voxel_token

# compare embedding initializations: random / rich8 / hexa9
python embedding_comparison.py --use_db --only random,rich8,hexa9 --max_samples 20000 --epochs 200

# dataset-subset comparison (all / rect-only / rect+load15)
python dataset_comparison.py --use_db --only all,rect_only,rect_load15
```

### 4. Evaluate

```bash
python evaluate.py --use_db --model ./models_voxel_token/model/best_model.pth --out ./plots/eval_sci
```

### 5. Ablation study (16 variants)

```bash
python ablation.py --use_db --max_samples 5000 --epochs 60          # all variants
python ablation.py --only full_token,no_token --use_db              # token vs physics-feature
python ablation.py --resume --use_db                                # resume incomplete
```

### 6. Analysis & visualization

```bash
python dataset_analysis.py --out ./plots/sci/dataset --csv ./data   # dataset distributions + CSV
python sample_diversity.py --num 20000 --out ./plots/sci/diversity  # feature-space diversity
python analyze_voxel_vocab.py --modes --vocab-file cache/voxel_vocab.pkl   # vocabulary PCA
python plot_sample_structures.py --num 10 --out ./plots/samples     # structure figures
python visualize_comprehensive.py --source db --num 8 --output ./plots/sci
python visualize_frame_cell.py --struct 3350                        # triptych encoding figure
```

## 📈 Representative Results

Model trained with token encoding (`VOXEL_TOKEN_INIT_PHYSICS='rich8'`), 4,000 validation samples:

| Subset | Overall R² | Peak R² | Rel. MAE | RMSE (mm) |
|---|---|---|---|---|
| **All structures** | **0.935** | **0.970** | **3.8%** | 3.56 |
| Rect-only | 0.944 | 0.974 | 3.7% | 2.94 |

> `rect_load15` (rect + all floors 15 kPa) shows much lower R² (0.006) — driven by only 221 available samples, illustrating the strong dependence of surrogate accuracy on dataset size.

## 🛠 Troubleshooting

| Issue | Fix |
|---|---|
| `python` not found / no numpy | Use the full env path, e.g. `C:\Users\admin\.conda\envs\sam3\python.exe`, or set the VS Code interpreter. |
| Training hangs at "load voxel cache" | First run loads a ~21 GB `cache/voxel_features_cache_token.pkl`; be patient (several minutes) and ensure ≥32 GB RAM. |
| `evaluate` differs from training | Always use the **same `--max_samples`** (shared `cache/dataset_split.pkl` validation split). |
| DB tables empty | Run `python db_setup.py` then `python db_generate_samples.py`. |
| Low R² | Try `LOSS_NORM='relative'`; check per-bin (small/large displacement) R² from `evaluate.py`. |
